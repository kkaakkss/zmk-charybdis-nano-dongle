# OLED 뽀모도로

선택한 **기존 구성 유지** 시안을 적용했다. USB/BLE·배터리·잠금·수정키·봉고캣·레이어의
기존 위치는 유지하고 왼쪽 여백에 상태와 남은 시간을 표시한다.

## 조작

먼저 기본 레이어의 **S+D+F**로 OSL을 켜고 세 키를 놓는다. 이후 아래 두 키를 함께 누른다.
글자는 기본 레이어의 물리 위치이며, OSL에서 실제 출력되는 F키/단축키 이름이 아니다.

| OSL 콤보 | 동작 |
|---|---|
| **W+O** (위치 1+8) | 시작 → 일시정지 → 재개. DONE 상태에서는 새 세션 시작 |
| **E+I** (위치 2+7) | 종료·초기화하고 타이머 표시 숨기기 |

두 콤보는 OSL에서만 동작하며 기존 50개 콤보를 유지한다. 시작/초기화에 키를 놓는 동작은
추가 입력을 만들지 않는다. 50ms 이내 동시 누름을 사용한다.

## 화면과 주기

- `FOCUS 25:00`: 집중 25분.
- `BREAK 05:00`: 휴식 5분으로 자동 전환하고 다음 집중 시작.
- `PAUSE`: 현재 집중/휴식을 일시정지. 다시 시작하면 남은 시간부터 재개.
- 집중을 4번 완료하면 `DONE 00:00`. 마지막 집중 뒤에는 추가 휴식 없이 종료한다.
  총 시간은 집중 4×25분 + 휴식 3×5분 = 115분이다. 긴 휴식이나 무한 반복은 넣지 않았다.
- 진행 표시는 네 점으로 나타낸다. 현재까지의 회차는 큰 점, 이후 회차는 작은 점이다.
  단색 OLED라 미리보기의 회색 대신 점의 크기로 구분한다.

실제 기존 수정키 컨테이너는 높이 17px여서 잠금 표시는 y=36부터 시작한다.
타이머는 x=0, y=18/27의 UNSCII 9px 높이 두 줄과 x=50부터의 진행 점으로 배치했다.
시안보다 1–2px 위로 맞춰 기존 잠금 표시와 겹치지 않게 했다.

## 5분 화면 꺼짐

화면은 기존대로 5분 무입력 후 꺼진다. 계산은 동글 커널의 64비트 uptime과 종료 시각을
사용하므로 화면 갱신이 멈춰도 시간이 계속 흐른다. 작업이 늦게 실행되면 경과한 단계를 따라잡는다.

집중·휴식 전환 및 DONE 때는 화면을 약 15초 깨운다. 그동안 입력이 없고 여전히 유휴 상태라면
다시 끈다. 입력이 있었다면 일반적인 5분 유휴 정책을 따른다. 가짜 키 입력이나 PC 알림은 보내지 않는다.
소리·깜빡임은 넣지 않았다. 현재 단계를 표시하는 화면 깨우기로 알린다.

동글 전원 분리·재부팅 시 초기화된다. Flash에 주기적으로 저장하거나 PC 시계를 동기화하지 않는다.
USB 절전에서 MCU의 uptime 진행 자체가 멈추는 경우까지 실제 시각과 일치한다고 보증하지 않는다.

## 구현과 검증

- `src/pomodoro_logic.h`: 순수 시간/단계 모델.
- `src/pomodoro.c`: 중앙 동작, 상태 잠금, 주기 작업. 기본/Studio에서도 콤보 바인딩은 유효하다.
- `widgets/pomodoro.c`: 기존 display 전용 작업 큐에서만 LVGL과 화면 드라이버 호출.
  고정 ZMK의 `unblank_display_cb`/`blank_display_cb`를 작은 어댑터로 사용한다.
  ZMK 버전을 변경할 때 해당 심벌과 유휴 동작을 다시 검증한다.
- 새 라벨/진행 표시의 할당 여유를 위해 LVGL 힙을 8KiB에서 12KiB로 늘렸다.
  1비트 전체 프레임버퍼와 4096바이트 전용 작업 큐 스택은 유지한다.
- `scripts/test-pomodoro.py`: 실제 모델·동작·위젯 C를 ARM 에뮬레이션 또는 호스트 UBSan으로 검사.
  6,900회의 1초 진행, 전체 주기와 지연 복귀, 경계 시점 일시정지, 초기화/재시작,
  32비트 범위를 넘는 uptime, UI 큐/배치 범위, 15초 깨우기/재소등, 유휴 이벤트 경합을 확인한다.
  커널·큐·LVGL·디스플레이는 테스트 더블이며 실물 렌더링/할당/동시성 검사는 아니다.

키맵 그림에도 새 콤보가 포함된다. 화면 표시·클릭·USB/BLE와의 동시 사용, 실제 5분 꺼짐과
단계 종료 알림의 최종 확인은 실기기에서 해야 한다. 동글 OLED UF2만 바꾸며 좌우 재설치는 필요 없다.
