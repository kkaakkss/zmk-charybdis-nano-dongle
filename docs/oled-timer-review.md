# OLED 타이머 검토 — 구현하지 않음

현재 128×64 SH1106와 LVGL 8 기반 상태 화면에 카운트다운·스톱워치를 추가할 수 있다.
동글만 업데이트하는 방식으로 가능하다. 이번 변경은 이 문서의 검토까지만 포함하며,
타이머 코드·조작 키·화면 위젯은 추가하지 않는다.

## 가능한 기능

| 방식 | 표시/조작 예 | 추가 작업 |
|---|---|---|
| 카운트다운 | 25:00 → 00:00, 시작/일시정지/재개/초기화 | 상태 모델, 키 behavior, 화면 위젯 |
| 스톱워치 | 00:00부터 경과 시간 표시 | 같은 시간 기반과 조작 재사용 |
| 뽀모도로 | 집중 25분·휴식 5분 전환 | 위 기능에 단계 전환·반복 정책 추가 |

첫 구현 후보는 고정 시간 카운트다운과 시작/일시정지·초기화다.
정확한 기능과 조작 키는 사용자의 선택 후 정한다. 현재 키맵을 임의로 차지하지 않는다.

## 화면 공간

현재 봉고캣·레이어·상태·수정키가 128×64를 공유한다. 작은 MM:SS 표시를 여백에 넣거나,
큰 글씨가 필요하면 타이머 전용 페이지로 전환하는 방법이 있다. 정확한 위치는 현재 위젯들과
실제 렌더링을 비교한 뒤 확정해야 한다. 초당 숫자 라벨만 갱신하면 되므로 전체 화면을
계속 다시 그리거나 새 프레임버퍼를 추가할 필요는 없다.

## 5분 화면 꺼짐과의 관계

현재 ZMK는 화면을 끌 때 display tick 타이머도 정지한다. 따라서 LVGL 콜백 호출 횟수를
1초씩 세는 구현은 피한다. 커널의 monotonic uptime에서 종료 시각·누적 정지 시간을 계산하고,
화면 갱신은 기존 전용 display 작업 큐에서 수행하는 방식이 적합하다.

- 단순한 방식: 5분 뒤 화면은 꺼지고 타이머 시간은 계속 흐른다. 다음 입력 때 남은 시간이나
  종료 상태를 복원한다. 표시 갱신이 멈춰도 실제 카운트다운은 늦어지지 않는다.
- 종료 때 화면 깨우기/깜빡임: 가능하지만 ZMK의 유휴 blanking·display tick 재시작과 연동하는
  별도 설계가 필요하다. 타이머 표시만 추가한다고 자동으로 되는 기능은 아니다.
- 실행 중 계속 화면 켜기: 가능하나 이번 5분 유휴 정책과 다른 예외 규칙이므로 별도 선택이다.

기본 장치에 부저가 설정돼 있지 않아 소리 알림은 별도 하드웨어가 필요하다.
PC 알림을 띄우려면 PC 측 프로그램이나 별도 통신 연동도 필요하다.

## 안정성과 제한

콜백에서 sleep/긴 루프/I2C 대기를 직접 수행하지 않고, 기존 LVGL 전용 작업 큐에서
짧게 라벨을 갱신한다. USB/BLE 시스템 큐를 막지 않는 것이 OLED 복구 때의 설계와 일치한다.
매초 flash 저장은 하지 않는다. 첫 버전은 동글 전원이 끊기거나 재부팅하면 타이머가 초기화되는
RAM 기반 방식이 단순하다. 전원 차단 후 복원·실제 시각 표시는 별도의 보존/시간 동기화 설계가 필요하다.

실제 구현 시 확인할 항목은 시작/정지/재개, 00:00, 모드 전환, 5분 화면 꺼짐과 복귀,
동시 타이핑·트랙볼·USB 재연결, 장시간 오차다. 지금은 코드나 실기기로 검증한 기능이 아니다.
